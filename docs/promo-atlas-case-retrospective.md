## 0. 结论先说

这不是「一次生成小红书图」的任务，是一条**用真实稿子反复打脸、再把每次差评变成可阻断门禁**的技能演进链：

- 用户最初只说了一句「这是一份保险说明，转为图文并茂的连环画」；**需求不是一次提完的**，而是每交付一版，就从成品里长出新的一句要求：要能上社媒 → 要支持金融品类 → 要说人话 → 不要煽情 → 要长图 → 四格要讲规则不讲处境 → 为什么有效信息这么少 → 尺寸为什么不是精确值。
- 对应地，`promo-atlas` 从 10-30 建成的首版走到 11-06 的 **1.2.1**，五个版本（1.0.2 / 1.1.0 / 1.1.1 / 1.2.0 / 1.2.1），冒烟断言从 **0 → 48 条**；每次升级都能对上一句具体的用户意见，没有一次是「顺手重构」。
- 两次最关键的转折都不是"文笔问题"：11-03 的「文案太煽情」查出**管线里没有任何一步问过基调**；11-06 的「有效信息太少」查出**所有门禁都在查不出错，没有一条在查说了什么**。结论一致——**该修的是 skill，不是那份稿子**。
- 最终稿用户 11-08 表示「这次的结果很满意」，但**仍不可发布**：3 处【待补】披露、合规签字、品牌口径与发布主体资质未关闭。满意的是画面与信息密度，卡住的是合规前置，两件事不矛盾。

**材料的边界**：本文依据本机历史会话日志（用户消息与助手结论）、两份本地复查报告、资料库交付清单、`SKILL.md` 变更记录与 GitHub 提交记录写成，全部可回溯；11-08 会话里关于小红书资质与法规的核查结论属于当时的联网结果，发布前须重新核对。索引见附录。

## 2. 分阶段复盘

### 阶段 0 · 需求起点：先有"能出图"，才有"能投放"（10-27 ~ 10-29）

> 「这是一份保险说明，阅读它并调用 novel-atlas 技能，转为图文并茂的连环画效果。」
>
> ——10-28 第一条需求；此时还没有「推广物料」这个概念。

`novel-atlas` 是把长文本压成一张带坐标约定的图，核心是「blueprint 是唯一事实来源、三道闸门设在花钱之前、AI 画景 / 代码写字、审核结论绑定图片 hash」。用户先拿一份保险条款截图去套这个技能，得到水彩九格连环画 [P2]；随后又在 10-29 追问「是否排除视频、能否扩到微博」「**文案是否经过去 AI 味检查**」，并要求换钢笔画画风重出 [P3]。

这三轮里已经埋下后面所有约束的雏形：**渠道适配**、**文案质量**、**同素材多版重出**。但那时还没有"推广物料"这个概念，产物只是好看的图文。

### 阶段 1 · promo-atlas 诞生，以及三条追加约束（10-30 上午）

> 「宣传载体是社交媒体，最终产物的形式要适配；不只是实物商品，理财、保险等金融商品也应当支持。」
>
> ——10-30 11:18；两条追加都动到布局层与合规策略。

用户要求「基于 novel-atlas 的设计，编写一个适用商业推广的 skill」[S1]。设计过程用 grill-me 逐分支收口，五个决定依次是：新品上市战役总览 → 以目标用户为轴 → 几何预留贴图位（产品 / logo / 吉祥物三视图不可重绘）→ 人群 × 场景矩阵 + 顶部时间轴 → 不做广告法词表扫描，**只做"能否指回素材"的溯源**。首版 12 条硬规则、9 步工作流、7 个脚本 2454 行，demo 全链路跑通；过程中修掉三个真 bug（大格小字、caption 矩形坐标系混用、lint 误判绝对化）。

接着用户三条追加，条条动到骨架层：

1. **「宣传载体是社交媒体」** → 真正要改的不是比例，是**平台 UI 压在画面上**：安全区改成四边不对称留白（抖音右侧 11% / 底部 11%，小红书底部 7%）、轮播每页自带标题页码披露、按平台真实像素出图。重排第一版做成"加白边"时 9:16 留白 79%，改成按比例反解格子形状后降到 2.6%。
2. **「理财、保险等金融商品也应支持」** → 推翻了刚定的"忠实于素材即可"：实物走 `trace_only`，金融/保险走 `strict`（收益承诺硬拦截 + 机构全称 / 资质编号 / 风险等级 / 数据截至日 / ≥2 条风险披露）。理由写得很直白：客户素材里写着"稳健保本"，忠实照排就是行政处罚。
3. **「文案是否经过'说人话'修正」** → 如实回答"没有"，承认漏了 `copy-voice.md` 是结构性缺口；用 humanizer-zh 的 31 条审自己写的 24 条 demo，发现 12 条里 9 条没有任何具体物件；新增**具体物件覆盖率 <50% 阻断 / <66% 提醒**，第一版实测 33% 被自己拦下。同时留下一条诚实的边界：脚本能阻止空句子上线，做不到让句子值得印。

### 阶段 2 · 第一次体检：先建可验证性，再改代码（10-30 中午）

> 「先冒烟脚本。」
>
> ——10-30 13:10；四个字决定了后面四轮敢改骨架层。

用户「检查这个 skill 是否有需要优化的部分」[S2]。审计结论不是"写得不好"，而是**它从未被完整跑过一遍**：7 处文档与实现脱节，其中 `--draft` 是死参数、`--demo-finance` 脚本里有而 `SKILL.md` 通篇未提（金融是差异化能力却不可发现）、`tests/` 不存在、`build/` 是空目录。

用户先选「先冒烟脚本」，然后依次「一起改掉」「删重复换成跳转」「加这条断言」「保持不动」。冒烟第一次运行就抓到两个只有实跑才会暴露的 bug：`--target` 默认值是字面量 `"main"` 而蓝图里叫 `master`（**文档里的主命令第一步就失败**）；失败原因无条件打印"缺 tile 或资产"，把披露超版面的错误归错类。最后 25 条断言，包含两条刻意设计的反向断言（删掉的参数不许悄悄回来），以及故意破坏平台表来证明 docs↔code parity 断言真的会失败。规则从 16 条合并到 14 条，三处重复解释改成指针。

这一轮不改变任何对外能力，却决定了后面四轮敢改代码：**每次改完都能十几秒内知道有没有弄坏**。

### 阶段 3 · 第一批实稿：判定标准从"闸门全绿"变成"逐格看像素"（10-30 下午 ~ 11-03 上午）

> 「把图片和文案使用 skill 检查一下，是否存在问题。」
>
> ——10-30 14:24；闸门全绿之后，人还得逐格看图。

第一份 5 页轮播交付后，用户要求「把图片和文案使用 skill 检查一下，是否存在问题」[S3]。脚本四道闸门全过（0 硬错误 / 12 格审计 pass / hash 全对），AI 逐格核像素后仍发现 4 处真问题，**其中 1 处是审计记录在说谎**。这个动作后来在 11-05、11-06 各重复了一次，成为固定纪律：台账不能替代看图。

11-03 08:31 重做时，把 5 页 2×2 改成 14 页一页一格，最实质的理由不是排版好看，而是上一版披露文字只有 13px、手机上约 4pt 读不了——**保险画面的风险提示读不了，是合规问题**。

### 阶段 4 · 两句差评 → 两个版本（11-03）

> 「每个四格漫画的文案不应该是讲故事，而是该场景下的规则解读。」
>
> ——11-03 15:13；一句话把 v1.1.0 又推进成 v1.1.1。

用户 11:17 同时点了两条 [S4]：**「文案偏向感性，煽情内容较多，需要在 skill 添加提问流程，确定文案基调」**、**「线上媒体基本全部支持长图查看，可以输出长图，比例暂定不超过 1:4」**。

- 根因不在文笔：上一单 12 条 caption 具体物件覆盖率 100%、硬错误 0，客户仍判"太煽情"，因为挑的全是最惨的一晚（孩子烧到 38.9 / 钥匙攥出汗 / 拖了半个月），而 `brief.py` 没有 `voice` 字段、`lint_copy.py` 查不出语气。→ **v1.1.0**：Step 0.5 五问（语气 / 人称 / 每条煽情词上限 / 金句配额 / 一句语感样例）、`brief.voice.tone` 缺失即阻断、苦情取材交叉判定、标题与正文一并盘账；长图 `1:4` 硬上限 + 分栏取场景数约数 + 人群按块落下；顺手修掉 `make_grid` 披露重试分支的 `TypeError`（只在版面真装不下时才触发，所以一直没暴露）。
- 15:04「使用专业语气，重新生成一次」→ 按 expert 基线重跑，插画复用、只改文案与版面。  
- 15:13「**每个四格漫画的文案不应该是讲故事，而是该场景下的规则解读**」→ 这句把 1.1.0 又推进一层：**v1.1.1** 新增 `caption_mode: narrative | rule`。`rule` 模式下 lint 换口径——不数具体物件，数规则要素（数字 / 条款要素 / 计量单位 / 条件），每条 caption 的 `caption_source` 必须 `client-confirmed:*`，**不然就是替保险产品立规**。12 格重写成「挂号费与诊疗费算同一笔门诊」「社保结算后余额按 80%」「单次上限 800 元」这类句子；画面管"什么时候"，说明板管"怎么算"。冒烟 31 → 32 断言。

> 事后看，v1.1.1 埋了一个缺口：文案模式改了，**画面语法没跟着改**。11-06 的"有效信息太少"有一半根子在这里。

## 5. 沉淀下来的做法

1. **把主观差评翻译成可阻断的机器检查。** 「太煽情」→ `voice.tone` + 煽情词预算 + 苦情取材交叉判定；「有效信息少」→ `key_facts` + 每格新增事实 + 信息面积比。改在门禁里，同类稿子才不会下次再犯；只改这一稿，等于把问题留给下一单。
2. **"有文件"不等于"有内容"，"台账说有"不等于"画面印了"。** 同一类脱节出现三次：8 张空白几何卡（`placeholder: 0`）、封面结论写四个数字却只印三个、落版 4 条 facts 由手写合并句覆盖而非逐字可核。前两次改成了硬门禁，第三次作为已知取舍记在报告里。
3. **门禁的目标若是"不出错"，全绿与"什么都没说"完全兼容。** 每加一条规则都该问：它拦的是哪一类失败？11-06 之前所有闸门都在查溯源、合规、几何、风格，没有一条问「读者从这一格拿走了什么新事实」。
4. **改文案模式必须同步改视觉语法。** v1.1.1 把 caption 从"画了什么"改成"按哪条算"，却没定义"规则怎么画"，加上 `no numbers` 的禁令，合规画法只剩空白纸片。修法是 `no invented numbers` + `[DATA-SLOT]`：模型画承载面，代码印客户确认的数字，合规口径一点没松。
5. **基调必须先问，事后无法达成一致。** 「这句是不是太煽情」没有可对照的基线就永远吵不完；Step 0.5 的五问连同语感样例写进 `brief.voice`，Gate 1 原样贴给客户看。
6. **先建可验证性，再改代码。** 10-30 中午那条"先冒烟脚本"的价值不在测试本身，而在于后面四次改骨架层时都敢动手；断言还要验证"人为破坏时真的会失败"，否则只是永远返回 true 的装饰。
7. **合规策略按品类分开，且 AI 不代填。** 实物走"忠实于素材"，金融走"披露 + 拦截"；3 处【待补】与合规签字从 11-05 保留到 11-08，一次都没被自动补成看起来合法的样子。发布主体资质、账号认证、点发布留给用户本人。
8. **复用已付费资产。** hash 绑定审计的设计让 11-03、11-06 两次返工都能只换文案与版式，4 张插画 sha256 不变、审计结论继续有效，不重复消耗出图额度。
9. **结构跟着事实走，而不是事实迁就矩阵。** 3 人群 × 4 场景其实是「三种适用情形 × 四个流程节点」，10 条事实硬摊进 12 格必然产生伪交叉。阶段三 `rulebook` 是正解，但被理性地排到真实投放之后。
