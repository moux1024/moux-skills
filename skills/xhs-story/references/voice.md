# 文案：平台规范、AI 味、脱敏

## 一、平台硬规范（写死，不用查）

| 项 | 规格 | 说明 |
|---|---|---|
| 标题 | ≤ 20 字 | 超出在信息流被截断，钩子必须落在前 20 字内 |
| 正文 | ≤ 1000 字 | 首屏只露前 3 行，这 3 行决定完读 |
| 图片 | 1–18 张，3:4 最优 | 1242×1660；首图即封面，决定点击率 |
| 话题 | 4–6 个 | 1–2 个大词带曝光 + 3–4 个精准小词 |
| emoji | 每页 ≤ 2 个 | 多了显廉价，且会被判为营销号 |

**标题三公式**（选一个，别混）：
- 数字反差：`从 0 到 7 张图，我只说了 3 句话`
- 反常识断言：`AI 写得越好，我越不敢发`
- 身份代入：`不会写代码的人，怎么把想法做成产品`

**正文结构**：前三行复述痛点（不是背景介绍）→ 中间按四段走 → 最后一行为一句可截图的话 → 空一行 → 话题。

## 二、违禁与限流

不能写：
- 绝对化用语：最、第一、顶级、绝对、100%、全网唯一、永久
- 效果承诺：包过、稳赚、保证、一定、彻底解决
- 导流：微信号、二维码、加我、私信我发你、链接见评论
- 平台名引流：`vx`、`威信`、`+V`、`dddd`

高风险词替代：
| 别写 | 改写成 |
|---|---|
| 最好用 | 我目前留着没删的 |
| 效率提升 300% | 原来两小时，现在十几分钟 |
| 彻底解决 | 到这一步基本不用管了 |
| 免费送 | 需要的可以看评论区第一条 |

## 三、AI 味黑名单

读者划走往往不是因为内容，是因为**语气**。以下句式出现任意两条，整篇可信度崩。

**禁用句式**
- 「不仅仅是……而是……」／「不只是……更是……」
- 「在这个 XX 的时代」／「随着……的发展」
- 「让我意识到」／「我深刻地体会到」／「不得不说」
- 「值得一提的是」／「值得注意的是」／「综上所述」
- 「首先……其次……最后……」三连（正文里别用，图里可以用）
- 「赋能」「抓手」「闭环」「颗粒度」「底层逻辑」
- 「希望对大家有帮助」「欢迎在评论区交流」

**禁用写法**
- 破折号滥用（一段里超过一个）
- 每段都是三行排比
- 每个形容词都配一个副词（「非常」「极其」「十分」）
- 通篇没有一句废话——真人的文章会有一句半句跑题的
- 每段都以总结句收尾（这是最重的 AI 味来源）

**该有的东西**
- 至少一个具体的、带有时间和数字的细节
- 至少一句自我否定或自嘲（「我一开始搞反了」）
- 段落长短不齐。真人的段落有的两行，有的八行

## 四、脱敏

**默认保守脱敏。只替换硬敏感项，保留项目名和工作内容。**

必换：
| 类型 | 处理 |
|---|---|
| 绝对路径 `/Users/xxx/...` | 「我的电脑」／「本地目录」 |
| 邮箱、手机号 | 直接删除 |
| API key / token / 密码 | 直接删除，且不要提示「此处有密钥」 |
| 内网 IP / 内部域名 | 「内网地址」 |
| 他人真实姓名 | 「同事」「我朋友」 |
| 客户公司名 | 「一个客户」 |

默认保留：自己的项目名、自己写的代码、产品名、公开的工具名。这些是故事的血肉，全隐掉就成通稿。

**流程要求**：渲染前把「被替换清单」贴给用户，一行一条，格式：

```
已脱敏：
- /Users/moux/WorkBuddy/... → 我的电脑
- xxx@mail.com → 已删除
未改动：xhs-story（项目名，保留）
```

不要静默改。用户有权知道哪几个字被吃掉了。

## 五、交付文案的格式

`caption.md` 必须一次成型、可直接全选粘贴，不要夹注释：

```
标题：<20 字内>

<正文，首屏三行是钩子>

<结尾那句可截图的话>

#话题1 #话题2 #话题3 #话题4

---
备选标题：
1. ...
2. ...
```

备选标题给 2 条——发布前你八成会想换一个。
